## 1. 🅰 프로젝트 톤·플레이어 정체성

**확정:** 저주받은 망자/기사 (다크소울 1 류)

### 1-1. 설정
- 잿빛 묘실에 갇혀 잠들었다가 어떤 계기로 깨어난 망자 기사.
- 묘실에서 탈출하기 위해 3단계 시련(Zone 1~3)을 돌파한다.
- 인간성·존엄을 거의 잃었지만 무기 사용 본능은 남아 있다.

### 1-2. 시각 톤
- 풀플레이트 갑옷, 어두운 색조 (검회색·녹슨 강철).
- 망토 또는 누더기로 실루엣 강조.
- 얼굴은 헬멧으로 가리거나 그림자 처리. 인간성 약화 연출.

### 1-3. 사운드 톤 (KiHoon 디렉션 출발점)
- **발소리:** 묵직한 메탈 + 스톤 마찰. Zone 재질에 따라 6종 분기 (`AI_AGENTS_GUIDE.md` §3-3 `OnFootstep`).
- **호흡:** 가쁘고 낮은 음역. 평상시 거의 무호흡, 회피·피격 시 짧은 거친 호흡.
- **갑옷 마찰:** 모든 동작에 미세한 메탈·가죽 마찰 레이어 (Idle/Walk/Run/Attack).
- **보이스:** 거의 무음. 사망 시에만 짧은 신음.

## 2. 🅰 캐릭터 무게감

**확정:** 다크소울식 묵직 (deliberate)

### 2-1. 이동·회피 체감 원칙
- 모든 액션이 **예고와 마무리**를 갖는다. 즉답형 인풋 없음.
- 회피: 짧고, i-frame 좁고, 후딜이 있다. "남발 불가"가 원칙.
- 스테미나 회복: 느림. 자원 관리가 게임의 핵심 긴장.
- 달리기: 스테미나 소모. 무한 sprint 불가.

### 2-2. 카메라 (§4 락온과 연동)
- 3인칭 어깨 너머. 자유 카메라 + 락온 카메라 2모드.

### 2-3. 사운드 함의
- 묵직한 발소리 = 카메라·무게중심 동기화 강조.
- 공격 휘두름: 길고 끝맺음이 분명한 swoosh. 콤보 인덱스별 분기 (`OnWeaponSwing(ComboIndex)`).
- 스테미나 고갈 시: 호흡 거칠어짐 + (선택) 짧은 큐 사운드.

## 3. 🅰 자원 모델

**확정:** HP + 스테미나 + 에스투스식 회복약

### 3-1. 자원 3종

| 자원 | 사용처 | 회복 방식 |
| :--- | :--- | :--- |
| **HP** | 피격 시 감소 | 회복약 사용 / Stage 클리어 시 풀회복 |
| **스테미나** | 공격·회피·달리기 시 소모 | 시간 경과 자동 (느림). 행동 중 회복 정지 |
| **회복약(에스투스)** | 사용 시 HP 즉시 회복 | Stage 시작 시 풀충전. Stage 내 추가 충전 없음 |

### 3-2. 회복약 동작 원칙
- 사용 입력 = 별도 키 (예: E 또는 1 — Skill 1 명세에서 확정).
- 사용 중 캐릭터는 **무방비 모션** (약 1~2초). 적 공격 시 캔슬되거나 그대로 피격 — 의도된 리스크.
- 횟수는 Stage 시작 시 결정. 정확한 수치는 Skill 1 명세에서 확정.

### 3-3. 사운드 시그니처 모먼트 #1 (KiHoon 작업 가이드)

회복약 사용은 본 데모의 **대표 시그니처 사운드 시퀀스**다.

```
[입력] → [병 꺼내기 모션 / 마개·액체 흔들림] → [꿀꺽 음] → [HP 회복 완료 큐]
```

**오디오 훅 계층 (D 검증 2026-05-29 분리 승인):**

- **코어 표준 5종** (`AI_AGENTS_GUIDE.md` §3-3) — 모든 캐릭터·전투의 공통 인터페이스. 본 데모 전체에서 유지되는 단일 표준. Skill별로 임의 확장·치환 금지.
  - `OnFootstep` / `OnWeaponSwing` / `OnEvadeStart` / `OnEvadeEnd` / `OnHitDamage`
- **Skill 1 확장 훅** — 회복약 전용 신설. 코어 표준과 **계층 분리**하여 Skill 1 범위에서만 존재.
  - `OnHealItemStart()` — 모션 시작
  - `OnHealItemDrink()` — 마시는 순간 (HP 회복 발효 시점)
  - `OnHealItemComplete()` — 회복 완료

훅 시그니처·Category 접두·호출 타임라인 최종안은 `Design/SKILL_01_COMBAT_SPEC.md`에서 확정한다.

## 4. 🅱 락온(Lock-on) 시스템

**P 권장:** 표준 락온 도입

### 4-1. 구성
- 입력: R-스틱 클릭(게임패드) / 마우스 휠 클릭(키보드) — Skill 1 명세에서 확정.
- 한 번에 1체만 락온. 락온 중 카메라가 적에게 부드럽게 고정.
- 거리 초과·시야 외 이탈 시 자동 해제.
- 락온 중 좌우 입력으로 타겟 전환 가능.

### 4-2. 카메라 거동
- 락온 시 카메라 거리·높이 약간 후퇴 (전투 가시성 확보).
- 락온 해제 시 자유 카메라로 즉시 복귀.

## 5. 🅱 사망·부활 모델

**P 권장:** Stage 시작점 리스폰. 페일런스·소울 회수 시스템 없음.

### 5-1. 동작
- HP 0 → 사망 모션 → "YOU DIED" 화면 → 페이드아웃 → Stage 시작점 리스폰.
- 적·환경 상태 초기화.
- 회복약 사용 횟수 풀충전.

### 5-2. 사운드 시그니처 모먼트 #2

```
[사망 보이스 (짧은 신음)] → [음악·환경음 절단] → [잔향 한 박자] → ["YOU DIED" 큐] → [정적]
→ [부활 시 환경음·음악 점진적 페이드인]
```

본 데모의 두 번째 시그니처 사운드 시퀀스. 사운드만으로 "죽었다"는 감각을 만들어내는 모먼트.

### 5-3. 데모 범위 외 명시
- 영구 사망, 소울 회수, 캠프파이어, 다회차 등은 **없음**.

## 6. 🅱 적 정의 스켈레톤

**P 권장:** 최소 표준 (소울라이크 기본형)

### 6-1. 공통 구성
모든 적은 다음을 가진다:
- HP, 공격력, 락온 가능 본 1개 (가슴 또는 머리).

### 6-2. 피격 반응 3종

| 반응 | 트리거 | 결과 |
| :--- | :--- | :--- |
| **휘청(Sway)** | 가벼운 공격 | 짧게 멈춤. 콤보로 연결 가능 |
| **다운(Knockdown)** | 강공격·콤보 마지막 타 (해금 후) | 큰 경직. 추가타 윈도우 발생 |
| **사망(Death)** | HP 0 | 사망 모션 후 콜리전 해제 |

### 6-3. AI 행동 골격 (Skill 1 범위 외 — 추후 명세)
- 기본 행동: 접근 → 공격 → 후퇴/리포지셔닝.
- Stage별 패턴 차별화는 별도 명세서에서 다룬다.

### 6-4. 사운드 함의
- §3-3 표준 훅 `OnHitDamage(HitLocation, Attacker)`로 타격음 분기.
- 휘청·다운·사망 각각 별도 큐 (KiHoon 매핑 영역).
- 적 자체 보이스(공격 외침, 피격 신음)도 Wwise 측에서 매핑.

## 7. 🅱 전투 철학 (Combat Philosophy)

**P 권장:** 기본 가드 없음. 회피 중심. 패링은 Stage 1 클리어 후 해금.

### 7-1. 이유
- `README.md` §1이 "약공격 + 회피 중심"으로 명시.
- 가드 도입 시: 가드 자세·임팩트·가드 깨짐 자원·애니·사운드 전체가 추가됨 → 데모 범위 폭증.
- 회피 중심이면 자원(스테미나)·타이밍·읽기가 단일 축으로 집중 → 포트폴리오 데모에 적합.

### 7-2. 해금 진행 (`README.md` §1 정합, KiHoon 갱신 2026-05-29)

| 시점 | 사용 가능 액션 |
| :--- | :--- |
| Stage 1 시작 | 기본 이동(**Run**), 달리기(Sprint), 약공격 **1·2·3타 콤보**, 회피, 회복약, 락온 |
| Stage 1 클리어 후 | 강공격, 패링, 다운 반응 활용 해금 |
| Stage 2 클리어 후 | 궁극기(불 마법 프로젝타일) 해금 |
| Stage 3 | 위 전체 활용 |

> **Skill 1 명세는 "Stage 1 시작 가능 액션"을 최소 단위로 설계**하고, 강공격·패링·궁극기는 후속 명세서에서 다룬다. KiHoon 2026-05-29 갱신: 기본 이동 상태는 Run(Walk 상태 제거), 약공격은 시작부터 1-2-3 콤보 제공.

### 7-3. 사운드 함의
- 회피·약공격이 본 데모 전체 시간의 80% 이상 차지 → KiHoon은 두 액션의 사운드 완성도에 우선 투자.

## 8. 입력 매핑 기본 원칙

**KiHoon 위임 2026-05-29 — P 확정. 다크소울 클래식 패턴 채택.**

- **회피·달리기 통합 입력 (`IA_EvadeSprint`):** tap = 회피 / hold = 달리기.
- **약공격 (`IA_Attack`):** 마우스 왼쪽 또는 R1/RB — 1·2·3타 콤보 입력.
- **강공격:** 마우스 오른쪽 또는 R2/RT — Stage 1 클리어 후 해금 (Skill 1B 명세).
- **락온 (`IA_LockOn`):** 마우스 휠 클릭 또는 R3.
- **회복약 (`IA_Heal`):** E 또는 X(Xbox).
- 모든 매핑은 Enhanced Input(`Content/Input/IMC_Default`) 위에 구성.

세부 키 바인딩·tap/hold 안전장치 수치는 `Design/SKILL_01_COMBAT_SPEC.md` §4에서 확정.

## 9. 재미 요소 (Fun Pillars)

본 데모가 플레이어에게 주려는 **체감 6가지**:

1. **자원 긴장 (스테미나):** "한 번 더 공격할까, 회피용으로 남길까"의 매 순간 선택.
2. **회피 타이밍의 쾌감:** i-frame이 좁아서 잘 빠진 회피는 명확한 성공 피드백.
3. **묵직한 피드백:** 약공격에도 무게가 실려 있어 적이 휘청이는 시각·청각 반응.
4. **회복약의 의례감:** 위기 상황에서 회복약을 마시는 순간의 무방비 긴장.
5. **해금의 보상감:** Stage 1 클리어 후 강공격·패링이 열릴 때의 "내가 강해졌다" 체감.
6. **사망의 의미:** 죽음이 페널티가 아니라 "다시 한 번 더 잘해보자"가 되는 단순 리스폰 루프.

이 6개 체감이 **Skill 1 수치 설계의 평가 기준**이다. 수치가 이 체감을 깎는다면 수치를 다시 잡는다.

## 10. 데모 범위 외 — 정의 안 함 결정

다음은 의도적으로 **정의하지 않음.** 추후 KiHoon이 명시 지시할 때까지 구현 금지.

- 장비·인벤토리 시스템 (무기 1개 고정)
- 레벨업·스탯 성장 (Strength/Dex 등 캐릭터 빌드)
- 화폐·상점·NPC 대화
- 다양한 무기군 (검·창·도끼 분기)
- 멀티 세이브 슬롯·이어하기 (Stage 진입점 단순 리스폰으로 대체)
- 멀티플레이·코옵
- 액세서리·반지·치장 슬롯
- 카메라 흔들림·체이크 커스텀 시스템 (필요 시 UE 기본 활용)
